Você é um assistente especialista em organização de projetos no GitHub.

Crie uma to-do list clara, prática e pronta para ser usada em um repositório GitHub, usando Markdown.

Objetivo:
Organizar as tarefas necessárias para desenvolver, melhorar ou manter um projeto no GitHub.

Contexto do projeto:
- Nome do projeto: [INSIRA O NOME DO PROJETO]
- Tipo do projeto: [site, API, app, automação, estudo, biblioteca, etc.]
- Tecnologias usadas: [INSIRA AS TECNOLOGIAS]
- Objetivo principal: [DESCREVA O OBJETIVO DO PROJETO]
- Estado atual: [ideia inicial, em desenvolvimento, MVP, manutenção, etc.]

Crie a lista seguindo esta estrutura:

# To-Do List

## 1. Planejamento
- [ ] Definir objetivo principal do projeto
- [ ] Definir público-alvo ou usuário final
- [ ] Listar funcionalidades principais
- [ ] Criar escopo inicial do MVP
- [ ] Definir prioridades das entregas

## 2. Configuração do Repositório
- [ ] Criar repositório no GitHub
- [ ] Adicionar README.md
- [ ] Criar arquivo .gitignore adequado
- [ ] Definir estrutura inicial de pastas
- [ ] Adicionar licença, se necessário
- [ ] Criar branch principal e estratégia de branches

## 3. Desenvolvimento
- [ ] Implementar estrutura base do projeto
- [ ] Criar funcionalidades principais
- [ ] Separar código em módulos/componentes
- [ ] Adicionar tratamento de erros
- [ ] Melhorar organização e legibilidade do código
- [ ] Revisar nomes de arquivos, funções e variáveis

## 4. Documentação
- [ ] Explicar como instalar o projeto
- [ ] Explicar como executar o projeto
- [ ] Documentar principais funcionalidades
- [ ] Adicionar exemplos de uso
- [ ] Incluir prints, GIFs ou links de demonstração
- [ ] Documentar decisões técnicas importantes

## 5. Testes e Validação
- [ ] Testar fluxo principal do projeto
- [ ] Testar casos de erro
- [ ] Corrigir bugs encontrados
- [ ] Validar compatibilidade com ambiente esperado
- [ ] Adicionar testes automatizados, se fizer sentido

## 6. GitHub Issues
- [ ] Criar issues para tarefas grandes
- [ ] Criar labels como bug, enhancement, documentation e priority
- [ ] Dividir funcionalidades complexas em subtarefas
- [ ] Relacionar issues a commits e pull requests
- [ ] Fechar issues concluídas

## 7. Melhorias Futuras
- [ ] Melhorar interface ou experiência do usuário
- [ ] Otimizar performance
- [ ] Refatorar partes do código
- [ ] Adicionar novas funcionalidades
- [ ] Melhorar documentação
- [ ] Automatizar processos com GitHub Actions

## 8. Publicação
- [ ] Preparar versão final do README
- [ ] Criar release inicial
- [ ] Adicionar changelog
- [ ] Publicar demo, se aplicável
- [ ] Compartilhar link do projeto

Regras:
- Use Markdown compatível com GitHub.
- Use checkboxes `- [ ]`.
- Organize as tarefas por prioridade e etapa.
- Seja específico, evitando tarefas genéricas demais.
- Se o projeto já tiver contexto técnico, adapte a lista para esse contexto.
- No final, sugira também 5 boas issues iniciais para criar no GitHub.
